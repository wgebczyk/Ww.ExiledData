# UI design

The UI design of Ww.ExiledData: the rules the UI follows, a map of where each part of the design lives in the code, and pictures generated from the running app.

**The code is the design.** This folder never restates values that live in code (colors, sizes, paddings, texts). It holds:

| File | What | Kept up to date by |
|---|---|---|
| `README.md` | this map and the workflow | hand |
| [`principles.md`](principles.md) | rules every screen follows; they change rarely | hand |
| [`components.md`](components.md) | the style classes and controls, what each is for, and the screen inventory | hand (names only) |
| `tokens.json` | every color token in both themes, plus radii and fonts | generated from `Tokens.axaml`; a test fails when it is stale |
| `screens/*.png` | every page, window and dialog in the dark and light theme, with sample data | generated by the app's `--screenshot` mode |

## Where the design lives in the code

| Part | Source of truth |
|---|---|
| Color tokens (Dark and Light), radii, fonts | `src/Ww.ExiledData.App/Theme/Tokens.axaml` |
| Shared styles (buttons, chips, cards, tables, segmented toggles) | `src/Ww.ExiledData.App/Theme/Controls.axaml` |
| Mapping styles (mode tabs, icon buttons, currency cell, scan chips) and line icons | `src/Ww.ExiledData.App/Theme/MappingControls.axaml` |
| Settings styles (fields, steppers, hotkey recorder, nav) | `src/Ww.ExiledData.App/Theme/SettingsControls.axaml` |
| Custom drawn controls | `src/Ww.ExiledData.App/Controls/` |
| Screens and dialogs | `src/Ww.ExiledData.App/Views/` |
| UI texts, empty states, captions | the view models in `src/Ww.ExiledData.App/ViewModels/` |
| Game overlays (fixed colors, not themed) | `src/Ww.ExiledData.App/Overlay/` |
| Sample data for the screenshots | `src/Ww.ExiledData.App/Services/SampleMapping.cs` |

## Changing the UI

1. Change the code. New colors go into `Tokens.axaml` (both themes, same key); views reference them with `{DynamicResource ...}`.
2. Regenerate: `tools/design-ui/update.ps1` (or `update.sh`). It refreshes `tokens.json` and `screens/`.
3. Review the image diff in the pull request: it shows the change as the user will see it, in both themes.
4. If the change breaks or adds a rule, edit `principles.md`; if it adds or renames a style class, control or screen, edit `components.md`.

`dotnet test` fails when `tokens.json` does not match `Tokens.axaml`, when a token is missing in one theme, when a text pair falls below its contrast minimum, or when a UI file hard-codes a color (`ThemeTokensTests`).

## Proposing a new design

Explore a bigger change outside the repo first (a mockup, a design canvas, a sketch) and link it from the pull request or issue. Mockups are not kept here: once the change is built, the generated screenshots replace them. When an exploration needs to start from the current state, start from `screens/` and `tokens.json`, not from an older mockup.
